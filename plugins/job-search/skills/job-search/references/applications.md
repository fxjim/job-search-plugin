# Outcome evidence and prior history

This pilot ends with a reviewed packet. It does not submit, send, upload or create receipt records. Keep existing evaluated/prepared/submitted/responded history distinct when the user supplies prior records; do not rewrite or silently migrate another workflow's ledger.

When considering a duplicate, read only authorized prior history and preserve prior rejection, bounce, response or uncertain submission. Unknown outcomes require reconciliation before the user retries elsewhere. Exact company/title/canonical URL and ATS identity matter; a new URL for the same title/company needs review.

A form click is not receipt evidence. If the user later supplies a confirmation, distinguish their report from an inspected on-page or message receipt and note the job, destination, time and evidence. Email sent is not delivery. A correlated bounce supersedes a sent-only assumption; no bounce observed is not proof of delivery. Never infer a hiring outcome from an application confirmation. Keep such external history in user-owned notes; the pilot helper's receipt and sending transitions are disabled.
