# Guided setup

Open naturally: “I’ll help you find suitable roles and prepare applications using your own experience. We can start with research and drafts. Where would you like to work, and what roles are you aiming for?” Ask a few related questions per turn; reuse answers already supplied. Do not dump a form or ask the person to understand implementation details.

Collect and confirm:

- Location, acceptable commuting locations/time zones, remote versus hybrid/on-site, and relocation willingness. Remote does not mean worldwide eligibility.
- Role titles/seniority and industries, exclusions, employment/contract type, pay floor with currency and period. Separate base salary, OTE, bonus/equity, hourly and fixed-price contract values. Ask what matters when pay is undisclosed.
- Resume as a file or pasted text, portfolio/work samples and specific demonstrated contributions. They may continue research without a resume. Track claim, source, verification and AI attribution; never transfer an existing customer's data. Ask for missing dates/metrics rather than filling them in.
- Availability, start date, working hours and contract duration needs. Ask work authorization/sponsorship questions only for a relevant jurisdiction/application. Avoid collecting identity documents, birth date, protected traits or credentials. Unknown answers stay unknown.
- Sources they want to use and access they already have. Present the preloaded categories; employer ATS sources need the employer's actual board URL/token. Gmail is opt-in with an agreed search query/date window; Indeed means alert emails only. Upwork is optional and requires a currently supported connected tool. Connection/OAuth is a user-controlled step.
- Desired help: research only or research plus materials (default). This pilot stops at a reviewed packet; it does not offer assisted submission, upload, form filling, email sending, spending or outreach.

Before summarizing or saving, distinguish candidate-stated preferences, this package's coverage rules, and current tool/access limits. Every attributed candidate preference must have an actual statement or correction as its source; record that reference alongside the profile. Never convert a package default, restriction, helper result, inherited fixture or another person's choice into the candidate's answer. Missing preferences remain unknown. If a package restriction affects the search, explain it separately as a package limitation; confirmation of the candidate's profile does not turn that limitation into a personal preference. For example, a candidate who excludes sales roles has not thereby excluded prop-firm employers, even though this release filters those employers. Check each exclusion against its source before asking for confirmation or persisting the profile.

Show a compact setup summary and invite corrections. Save it only to a location the user accepts. The helper's `templates/profile.json` deliberately starts blank. A missing resume or eligibility answer need not block public research; it can block a final match or application. Record decisions as unknown or not-yet-available, not guessed facts. Save no secrets or tokens. Explain where local files will live and how the user can remove them. Do not promise encryption; host storage and account controls govern access.

Do not collect or record standing application authority in this preparation-only pilot. Setup/storage confirmation and exact-content review do not authorize external actions. A request to apply receives a reviewed-packet handoff; execution requires a separately supported workflow outside this pilot.

After setup, offer a small first pass through enabled sources, then bring the evaluated list and one reviewable packet. Do not create a recurring schedule by default.
