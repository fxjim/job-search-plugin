# Sources, freshness and matching

Read `config/sources.json` before configuring a route. It contains method references and the time/status of build verification. Those dates do not prove a posting is open today. A category enabled by default is offered during setup; it is not an account connection, scrape permission or configured employer target. No targets or account identifiers are preloaded.

Greenhouse requires an employer board token; Ashby requires an employer job-board name; Lever requires a site and region; Workable's public endpoint requires an employer account subdomain. Obtain identifiers from the employer's own link and retain its provenance. Never enumerate guessed tenants, request employer API keys, or claim a cross-employer global feed. Public GET methods are for reading published jobs. Record the official hosted application route for the user to inspect and use manually; this pilot does not fill or submit it.

YC, a16z and Cryptocurrency Jobs are starting points for limited discovery under current site rules. Verify the original employer page and active application route. Wellfound is preloaded as user-assisted: accept a supplied posting or supported authorized route, with no scraper. Breezy/Rippling/Gem/Jobvite routing follows the exact employer-published URL; a vendor's marketing page is not evidence that a customer's form works. Respect login walls, robots/access rules, rate limits and prohibitions. Do not replay private APIs discovered in browser traffic.

For Gmail, resolve the user's selected account and query, read only job alerts in scope and record message references. Indeed alert content is discovery only. Do not follow tracking links to Indeed or browse/apply there. Search independently for the named employer role; if unavailable, leave it unverified and give the user the alert reference. Never create alerts, subscribe, change mail or send messages as a side effect of reading.

Upwork must use its supported connector. Discover actual tools and current descriptions: account selection, marketplace search, full job details, previews and confirmations vary by surface. Do not silently substitute browser scraping. The package does not connect an account. Use only authorized read actions in this pilot. Do not buy or spend Connects, boost, submit proposals, message, accept contracts or invoke write previews. Those actions require a separate supported workflow and its confirmations. A preview or draft is not a submitted proposal; platform “Accepted” can mean a submitted/validated proposal rather than a contract win.

For each source check record `source_id`, exact URL/identifier, method, evidence reference, checked time, and `active`, `closed`, `blocked`, `stale`, `requires_connection`, or `unverified`. Failed retrieval is not “zero jobs.” After 30 days, recheck source-method documentation before relying on it. Posting checks older than 24 hours become stale; reverify before targeted preparation and advise the user to recheck immediately before any manual application. These are package defaults, not guarantees. Closed deadline, disappeared listing, job ID mismatch or inactive form overrides a recent timestamp.

For each candidate, store source URL plus canonical employer posting/application URL, company/title, ATS ID when available, publication date if present, and the observed application status. Canonicalization removes only recognized marketing parameters, keeping job identity parameters. Check exact company/title/URL and same ATS ID; same company/title at a new URL is a review warning. Inspect prior outcomes before creating a new record; a previous rejection, bounce or submission must not disappear.

This release's coverage policy excludes prop-firm providers and dedicated career boards; this is a product-scope choice, not a general financial-safety prohibition on researching employment. Attribute this filter to package scope, never to the candidate unless the candidate actually stated that preference. Keep the candidate's own exclusions separate, following the provenance check in [onboarding](onboarding.md). Apply the package's exclusion checks to the actual employer, domain, dedicated ATS board and business model, including aggregate results. The explicit list includes Tradeify, Topstep, MyFundedFutures/MyFundedPerps, Aqua, Lucid, Apex, FTMO, FundedNext and TakeProfitTrader; it is not exhaustive. Ambiguous names require identity review. Lucid Motors and unrelated Apex finance companies are not excluded merely for a shared word. Unverified employer classification remains a review blocker.

Match a requirement to cited evidence and an explanation of how it supports the claim. Mark demonstrated, partial, missing or unknown. The helper verifies references exist, not that semantic reasoning is correct: the agent must read the evidence. Keep hard requirements separate from preferences; show gaps, salary uncertainty and location/eligibility constraints. Do not turn keywords, self-reported confidence, AI-generated output or a team result into personal expertise/metrics. No unsupported match percentage.
